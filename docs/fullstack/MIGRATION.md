# Complete installation migration

Rehearse on a new private data volume using the Linux product image. The image serves the browser and replacement backend on one port. Import handlers require Linux descriptor confinement; run them through the product image rather than a macOS development server.

Stop writes to the original installation and make a closed, consistent SQLite snapshot. Preserve the original installation volume, media folders, metadata covers, configuration and image version. Mount the snapshot and original folders read-only into the replacement. Never point tests at owner data. The snapshot limit is256MiB; inventory limits are100,000 rows per table and500,000 total rows. Cover import accepts up to1,000 PNG/JPEG files, each at most5MiB, within128MiB total.

1. Import accounts during first-owner setup with the configured private setup key. Keep a local password owner for recovery. Existing passwords and account IDs retain their policies. OpenID-only ordinary accounts stage without password access.
2. Sign in as that owner. Inspect and import media with explicit original-to-mounted folder mappings. Review every error and archived field. Original item/file/episode IDs, progress, bookmarks and history retain associations.
3. Import lists and delivery from the same source digest. Select the replacement public URL explicitly. Collections, owner-private playlists, feed IDs/slugs/GUIDs, SMTP configuration and e-reader access rules retain their relations.
4. Inspect complete migration with the same source path and digest. Map the original metadata cover root onto a read-only import/media mount. Supply every exact original OpenID callback plus the replacement browser callback. Provider discovery must succeed. Linking uses the validated original issuer and subject; a matching name/email never links accounts.
5. Inspect the inventory of every table, column and nested JSON field. Every unsupported datum or migration error blocks cutover. Unknown nonempty tables/columns/extensions, author portraits, active old cron backups and nondefault per-podcast schedules/limits currently require resolution before cutover. Archive retention alone does not claim feature migration. Retired scanner/file-writing/log controls and old sign-in sessions are explicitly reported; originals remain privately archived.
6. Complete migration only after the report permits cutover. The operation makes a private pre-write backup, then atomically saves configuration, original OpenID identities, cover blobs, subscription state and its receipt. Repeating the same committed inputs returns the receipt; changing mappings, public URL or callbacks does not silently reapply it. Preserve the displayed rollback backup ID.
7. Verify browser, Android, Apple and TV against this image alone, including local and original OpenID sign-in, policy denial, media/reader access, private lists, published feeds and listening history. Restart the same image with the same volume and verify durable state again. Do not promote a partial-stage report as complete acceptance.

Use [RECOVERY.md](RECOVERY.md) to restore the pre-write backup into a new empty volume. Reattach the same media mounts. Sign in locally, because a login issued after the snapshot is absent from that snapshot. The pre-write state has four stage receipts and no newly enabled OpenID configuration. Keep the fully migrated volume intact until rollback acceptance passes. For rollback to the original product, stop the replacement and start the preserved original image/volume with its preserved media and configuration. Never run both writers against one data volume.

Only after rehearsal passes, arrange the live URL and one-image deployment. Preserve original backups and mounts through the accepted rollback window. Remove QA private-host exceptions and synthetic providers before public deployment. Source database/media hashes must remain unchanged throughout rehearsal.
